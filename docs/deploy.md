## 5. Function secrets

- ✅ `WAGGLE_APPROVAL_SECRET` (random, generated by the CLI session, never printed) and `WAGGLE_SITE_ORIGINS` set 2026-11-15.
- ✅ `WAGGLE_API_DB_URL` set 2026-11-15. To change it, put the line in a gitignored `.env.*` file and run `npx supabase secrets set --env-file <file>`; shell quoting (especially in cmd.exe) can save literal quotes into the value. The value looks like:

```bash
npx supabase secrets set WAGGLE_API_DB_URL='postgresql://waggle_api_login.wckkmbdfqeqgrispgdbx:<password>@aws-1-us-west-2.pooler.supabase.com:6543/postgres'
```

Full reference:

```bash
npx supabase secrets set \
  WAGGLE_API_DB_URL='postgresql://waggle_api_login.wckkmbdfqeqgrispgdbx:<password>@aws-1-us-west-2.pooler.supabase.com:6543/postgres' \
  WAGGLE_APPROVAL_SECRET='<random 32+ bytes>' \
  WAGGLE_SITE_ORIGINS='https://mattshelton777.github.io'
# Once a custom domain fronts the MCP endpoint:
npx supabase secrets set WAGGLE_PUBLIC_URL='https://<your-domain>/mcp'
```

Never set the service-role key on either function.

## 6. Deploy functions 🔁

- ✅ `mcp` and `connect-api` deployed 2026-11-15. Verified: `mcp` returns 401 with OAuth protected-resource metadata, `connect-api` answers CORS for the Pages origin and reaches the database.

```bash
npm run deploy:functions
```

Builds `supabase/functions/_shared/waggle.bundle.js` from `packages/server`, then deploys `mcp` and `connect-api` with gateway JWT checks off (both verify tokens in code). `--use-api` bundles on Supabase's side, so Docker isn't needed. The CLI asks for confirmation on hosted changes; answer yes.

Endpoints:
- MCP: `https://wckkmbdfqeqgrispgdbx.supabase.co/functions/v1/mcp`
- Connect API: `https://wckkmbdfqeqgrispgdbx.supabase.co/functions/v1/connect-api`

If you later serve MCP from a custom domain, update `mcpUrl` in `apps/connect/config.js` and set `WAGGLE_PUBLIC_URL`.
